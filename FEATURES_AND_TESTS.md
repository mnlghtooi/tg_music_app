# Music Lab v0.5.0 — функции и проверки
Дата: 18.10.2026. Реализация в index.html. Проверка в Telegram на физическом iPhone ещё не выполнена.
Автоматические проверки интерфейса выполнены в Chrome, экран 390×844; аудио и API подменены. Это не проверка реального звука, сети, iOS или фоновой работы.

## Поиск
- Кнопка поиска справа сверху открывает отдельный экран. Стрелка возвращает в библиотеку.
- При открытии отображается последний успешный набор найденных треков (не история прослушивания и не история всех запросов).
- Запрос и результаты сохраняются в localStorage musiclab_search_v1. После перезапуска восстанавливаются без запроса к API. Они могут устареть.
- Поиск по названию/исполнителю, Enter, популярные треки; ошибки сети и пустой ответ показываются отдельно. При ошибке предыдущий успешный список остаётся.
- Новая загрузка отменяет предыдущую; устаревший ответ не должен заменять актуальный.
- Поиск и навигация не меняют текущую очередь. Нажатие на название трека или «Слушать» в меню заменяет очередь результатами поиска.
- При старте приложения нет автоматического воспроизведения и фоновой загрузки популярных треков.
- В поиске оставлен диагностический запуск тестовых мелодий; он явно заменяет текущую очередь.

## Текущий трек
- Одинаковый source:id выделяет выбранный трек во всех отображаемых списках: поиск, избранное, пользовательский плейлист, очередь.
- В паузе выделение сохраняется с пунктирной рамкой. aria-current и текстовое описание сообщают состояние.
- При смене трека и автоматическом переходе выделение и нижняя плашка обновляются.
- Трек остаётся выбранным даже при ошибке потока; реальный статус ошибки доступен в диагностике. Выделение само по себе не доказывает воспроизведение.

## Нижняя плашка и плеер
- Плашка появляется после выбора трека. Обложка/заглушка, название, исполнитель, play/pause, следующий трек, индикатор прогресса.
- Нажатие на название/обложку раскрывает полноэкранный плеер внутри приложения. Кнопки play/pause и next не раскрывают его.
- Полный плеер: обложка, название, исполнитель, предыдущий/следующий трек, пауза, перемотка, время, лайк, дизлайк, добавление в плейлисты, очередь.
- Сворачивание плеера возвращает на прежний экран (включая поиск), не пересоздавая audio и не обрывая трек.
- Плашка доступна в библиотеке и поиске; в полном плеере скрыта под его экраном.
- Состояние playbackState передаётся в Media Session; метаданные и системная перемотка сохранены.
- Плеер не использует браузерный Fullscreen API: это экран приложения, системные элементы Telegram остаются под управлением Telegram.

## Библиотека и действия (включая v0.4.4)
- Избранное — общий список лайкнутых треков. Пользовательские плейлисты открываются нажатием на карточку.
- У названия карточки нет отдельных кнопок редактирования/удаления.
- Внутри: назад без текста, число треков, слушать, перемешать, меню ⋯. Переименование и удаление находятся в меню пользовательского плейлиста; системное избранное не удаляется и не переименовывается.
- У каждого трека в поиске/очереди/плейлисте — ⋯: слушать, добавить/убрать избранное, добавить в плейлист; внутри пользовательского плейлиста также удалить из него.
- Нижнее окно выбора плейлистов позволяет выбрать несколько, создать новый и сразу добавить трек.
- Лайк и дизлайк в полном плеере взаимоисключающие. Повторное нажатие снимает оценку. Дизлайк пока не переключает трек и не фильтрует поиск: рекомендательный режим ещё не реализован.
- Данные библиотеки используют прежний musiclab_library_v1. Изменение интерфейса не очищает библиотеку.
- Тестовые мелодии не добавляются в избранное/плейлисты.
- Диагностика свёрнута под отдельный раскрывающийся раздел.

## Экран блокировки — ключевое незавершённое требование
Play/pause, next/previous, метаданные и перемотка используют Media Session. Их реальная доступность зависит от устройства.
Лайк/дизлайк с заблокированного экрана НЕ реализованы в веб-версии и не считаются завершёнными. Исследование и следующий технический эксперимент: [LOCK_SCREEN.md](LOCK_SCREEN.md).

## Ручной чек-лист
Все пункты ниже НЕ ПРОВЕРЕНЫ на iPhone для v0.5.0. Отмечать только после реального теста, записывая модель, iOS, Telegram, версию приложения, результат и дату.

### Поиск
- [ ] Первый запуск без сохранённого поиска: библиотека открыта, звук не запускается, поиск доступен справа сверху.
- [ ] Поиск → результат → закрыть → открыть: список и введённый запрос сохранены.
- [ ] Перезапуск Mini App: последний успешный список восстановлен.
- [ ] Пустой запрос, нулевой ответ, offline, ограничение API: понятный статус, текущая музыка не прерывается.
- [ ] Два быстрых запроса: показываются результаты последнего.
- [ ] Поиск и популярные треки во время воспроизведения не меняют очередь и позицию.
- [ ] Выбор трека явно запускает именно его и новую очередь.

### Плеер и подсветка
- [ ] Трек подсвечен в поиске, избранном, пользовательском плейлисте и очереди; совпадение по source:id, а не названию.
- [ ] Пауза/возобновление из плашки отражается в полном плеере и выделении.
- [ ] Next/previous и автоматическое окончание меняют название, обложку, выделение и прогресс.
- [ ] Открыть/свернуть полный плеер из поиска и библиотеки: позиция, экран и звук сохранены.
- [ ] Перемотка до/после загрузки метаданных, длинный трек, отсутствующая обложка.
- [ ] Ошибка потока: диагностика сообщает ошибку, приложение не зависает.
- [ ] Длинные названия, 320/390/430 px, поворот, клавиатура, safe area: нет перекрытия кнопок и последнего трека плашкой.
- [ ] VoiceOver/клавиатура: названия кнопок, текущий трек, открытие/закрытие экранов и меню, возврат фокуса.

### Библиотека
- [ ] Старые избранное и плейлисты сохранились после обновления.
- [ ] Создать, открыть, переименовать, перемешать, удалить плейлист; отмена удаления.
- [ ] Добавить трек в несколько плейлистов; создать плейлист из окна добавления.
- [ ] Удаление трека из одного плейлиста не удаляет его из других и избранного, не обрывает текущую очередь.
- [ ] Лайк/повторный лайк/дизлайк/повторный дизлайк и сохранение после перезапуска.
- [ ] После оценки в полном плеере счётчики библиотеки обновляются.
- [ ] Пустые избранное/плейлист и отсутствие доступа к localStorage не ломают навигацию.

### Фон и система
- [ ] Реальный поток Audius играет при блокировке и переключается после окончания.
- [ ] Экран блокировки: play/pause, next/previous, метаданные, обложка, перемотка.
- [ ] Bluetooth-наушники, звонок/прерывание, возврат в Telegram, offline во время потока.
- [ ] Лайк и дизлайк без разблокировки — отдельная проверка нативного прототипа; в Mini App недоступны.

## Автоматическая проверка
Пройдены: восстановление поиска; отсутствие стартового воспроизведения/запросов; выбор трека; подсветка в поиске и плейлисте; плашка; открытие/сворачивание полного плеера; play/pause/next; меню трека; вызовы лайка/дизлайка; поиск без изменения проигрываемого трека; восстановление результатов после reload; отсутствие ошибок JavaScript. Звук подменён, поэтому тест не подтверждает качество воспроизведения.
