# Лайк и дизлайк с экрана блокировки — исследование
Дата: 18.10.2026.
Статус: ключевое требование пользователя, НЕ реализовано. Отдельный iOS-клиент пока не выбран и не создан.
Цель: оценить текущий трек без открытия приложения, по возможности без аутентификации, и надёжно сохранить оценку для рекомендаций.

## Что установлено
1. Веб-стандарт Media Session не содержит like/dislike actions. Установка произвольного имени не создаёт системную кнопку.
   Источник: https://www.w3.org/TR/mediasession/
2. Опубликованный Telegram Mini Apps API не предоставляет мост к MPRemoteCommandCenter или настройке системных аудиокнопок. Это вывод из перечня документированных API; наличие полноэкранного режима и ярлыка не даёт нативных аудиокоманд.
   Источник: https://core.telegram.org/bots/webapps
3. Нативный iOS MediaPlayer предоставляет MPRemoteCommandCenter.likeCommand и dislikeCommand (MPFeedbackCommand). Это подтверждает путь к регистрации обработчиков, но не гарантирует показ обеих кнопок на конкретном экране и версии iOS.
   Источники:
   - https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter/likecommand
   - https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter/dislikecommand
   - https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter/ratingcommand
4. Фоновый нативный плеер требует AVAudioSession playback и Background Modes/audio.
   Источник: https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback
5. Live Activities/WidgetKit позволяют свои кнопки через App Intents. Однако Apple прямо указывает, что на заблокированном устройстве кнопки/переключатели неактивны до аутентификации и разблокировки. Это не подтверждённый обход требования «без разблокировки».
   Источник: https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities

## Предлагаемая архитектура, если нативный эксперимент успешен
Telegram остаётся точкой входа и веб-интерфейсом. Для системного плеера требуется установленный iOS-клиент.
Нативная оболочка может переиспользовать веб-интерфейс, но владеть воспроизведением и очередью должен нативный AVPlayer/AVQueuePlayer, а не HTML audio в WKWebView.
Нативный слой: AVAudioSession, MPNowPlayingInfoCenter, MPRemoteCommandCenter, обработка аудиопрерываний, локальное сохранение оценок.
Общий идентификатор трека — source:id. Единая модель оценки: liked / disliked / neutral; повторное нажатие снимает оценку, взаимоисключение сохраняется.
При смене трека фиксировать его идентификатор в момент приёма команды, чтобы оценка не попала следующему треку. Действие должно сохраниться локально до сообщения об успехе.
Для одинаковой библиотеки в Telegram и нативном приложении потребуется серверная синхронизация/авторизация. localStorage Telegram и WKWebView/нативное хранилище не общие. Нельзя считать их синхронизированными без отдельной реализации.
Telegram может предлагать открыть установленный клиент по ссылке; такой сценарий требует явного действия пользователя, это не скрытое расширение возможностей Mini App.

## Критерий приёмки
Пользователь может поставить обе оценки текущему треку на экране блокировки, не открывая приложение; отдельно подтверждается требование отсутствия разблокировки.
Оценка сохраняется ровно нужному треку и отражается в библиотеке и будущем рекомендательном движке.
Если iOS скрывает одну из команд, требование не считается выполненным. Одного наличия API и успешной компиляции недостаточно.
