# Music Lab — проверка резервной копии библиотеки

**Реализация:** Music Lab v0.7.10, JSON format `musiclab-library` v1.
**Статус:** автоматические тесты есть; реальный экспорт и проверка iPhone ожидаются.

## Что есть в копии

- Лайки (любимые треки) и дизлайки.
- Плейлисты, их стабильные ID, названия, список треков с исходными `source:id`.
- Публичные метаданные треков (название, исполнитель, доступные ссылки на альбом/артиста).

**Не входят:** настройки интерфейса, очередь и текущая позиция плеера, аудиофайлы, сессии Telegram, ключи доступа. Не хранить JSON публично в репозитории.

## Как подтвердить на реальном iPhone без риска

1. Открыть **тот же домен**, на котором в «Моя музыка» реально видны нужные плейлисты и избранное. При каждой смене `*.trycloudflare.com` меняется origin и `localStorage` — пустая библиотека по новому URL **не означает**, что старая библиотека была перенесена.
2. Войти в «Моя музыка» → «Перенос музыки и резервная копия» → «Экспорт библиотеки».
3. Убедиться, что в сообщении указаны ожидаемые количества любимых треков и плейлистов. Сохранить `musiclab-library-YYYY-MM-DD.json` в приложение «Файлы» iPhone или другой приватный каталог **вне Safari/Telegram**.
4. В том же разделе выбрать этот файл в поле «Импорт JSON-копии Music Lab». Просмотр прочитает JSON и покажет числа: плейлисты, треки внутри них, лайки и дизлайки. До нажатия «Добавить к моей библиотеке» изменения не применяются.
5. Для первой приёмки **не нажимать «Добавить» на устройстве с оригинальной библиотекой**. Убедиться, что показанные числа совпадают с экспортом; файл остался в «Файлы», и все исходные плейлисты на месте.
6. Восстановление можно проверить позднее на отдельном тестовом браузере/устройстве или с заведомо пустой библиотекой, сравнив списки и повторив импорт (без дублей). Не удалять оригинал для теста.

**Если цифры неожиданно нулевые:** остановиться и найти домен/браузер, где данные действительно присутствуют. Не очищать Safari, Telegram WebView или данные сайтов; не создавать новые плейлисты вместо старых до выявления origin.

## Автоматические проверки

`tests/test_library_backup.cjs` проверяет сериализацию JSON, `validate`, источник треков, порядок и названия плейлистов, лайки и дизлайки, повторный merge без дублей, экспорт без изменения памяти, предпросмотр импорта без записи и отказ при плохом JSON. CI подключает файл в `.github/workflows/tests.yml`.

**Важно:** CI не может подтвердить, что реальный JSON был скачан на iPhone или что Safari/Telegram разрешил сохранение файла. Приёмка #14 остаётся открытой до подтверждения человеком.
