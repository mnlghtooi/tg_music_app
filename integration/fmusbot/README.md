# Проверка интеграции @fmusbot на Windows
Статус: подготовлен диагностический прототип. Реальный вход и ответ бота ещё не проверены.
Текущее приложение v0.5.2 продолжает использовать Audius. Этот скрипт не меняет библиотеку, не загружает аудио и не является готовым сервером.

## Что нужно
- Python 3.10+ на личном Windows-ПК.
- API ID и API hash своего приложения из https://my.telegram.org → API development tools.
- Telegram-аккаунт для локальной авторизации. Утилита имеет возможности Telegram-клиента; файл сессии позволяет действовать от имени аккаунта. Хранить его только локально.
- Для первого поиска используй название собственной/разрешённой композиции. Доступность файла через бота сама по себе не подтверждает права на распространение.

## Установка
Скачай эту папку через GitHub (Code → Download ZIP) и открой PowerShell в папке integration/fmusbot:
~~~powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe probe.py
~~~
Активация venv не требуется; менять ExecutionPolicy не нужно.
Утилита запросит API ID, API hash, телефон, код Telegram и пароль 2FA, если он включён. Секреты вводятся в локальный терминал, не в чат и не на GitHub. Повторный запуск использует локальную сессию.
Первый запуск без --query только проверяет метаданные @fmusbot и поддержку inline. Сообщений боту не отправляет.

## Один поисковый запрос
~~~powershell
.\.venv\Scripts\python.exe probe.py --query "название разрешённой композиции"
~~~
Отправляется ровно одно сообщение @fmusbot; 15 секунд собираются новые ответы и изменения ответов. Скрипт не нажимает кнопки, не подписывается на каналы и не скачивает файлы.
Во время теста не отправляй другие запросы этому боту: его ответы не всегда содержат связь с конкретным запросом.
Если бот требует /start, открой его вручную в Telegram, прочитай условия и запусти скрипт повторно после завершения предыдущего запроса.
Если metadata сообщает inline_available=true, можно отдельно проверить:
~~~powershell
.\.venv\Scripts\python.exe probe.py --mode inline --query "название разрешённой композиции"
~~~
Inline-проверка не публикует результаты ни в какой чат. Не запускай много проверок подряд. При FloodWait программа фиксирует время ожидания и заканчивает работу; ограничение не обходит.

## Что прислать для продолжения
Содержимое .private/probe-result.json после просмотра (убери личные данные из текста ответа, если они встретились).
НЕ присылай .session, API hash, пароль, номер телефона и коды входа.
Отчёт содержит типы медиа и подписи кнопок, но не callback data, URL файлов, access_hash и session auth key.
Если установка/вход не удались, достаточно названия ошибки из терминала.

## Дальнейшая интеграция после проверки
1. По реальному ответу выбрать chat/inline/API бота; не угадывать формат callback-кнопок.
2. Получить один разрешённый аудиофайл и проверить доступность потока на iPhone.
3. Поднять локальный Python backend с последовательной обработкой запросов и тайм-аутами.
4. Для Mini App на iPhone понадобится HTTPS-адрес backend, доступный с телефона. localhost Windows для телефона не подходит; GitHub Pages не запускает Python.
5. Перед публичным доступом: проверка Telegram initData на сервере, ограничение запросов/пользователей, хранение сессии и токена только на сервере, проверенные права на музыку.
6. Аудио выдавать по своему track ID, с поддержкой HTTP Range для перемотки; Telegram file reference не считать постоянным URL.
7. Подключить провайдер к поиску, избранному и очереди. Не заменять рабочий Audius до успешного сквозного теста.

## Чек-лист
- [ ] Python/зависимости устанавливаются на Windows.
- [ ] Вход и повторный запуск с локальной сессией.
- [ ] Цель действительно @fmusbot, без запроса бот является bot.
- [ ] Один chat-запрос → текст/кнопки/аудио; отметить необходимость /start.
- [ ] При наличии inline отдельно проверить один запрос.
- [ ] Пустой результат и тайм-аут различимы от успешного ответа.
- [ ] FloodWait не запускает повторный поиск автоматически.
- [ ] Секреты и сессия не попадают в GitHub/отчёт.
- [ ] Реальное аудио/поток, HTTP Range, iPhone и фон — отдельный следующий тест, пока не выполнен.

## Основания
- Telethon 1.45.0, авторизация: https://docs.telethon.dev/en/stable/basic/signing-in.html
- Telethon client API: https://docs.telethon.dev/en/stable/modules/client.html
- Telegram bot-to-bot: https://core.telegram.org/api/bots/bot-to-bot
  Прямой личный диалог требует включения режима у ОБОИХ ботов. Настройка @fmusbot не подтверждена.
- Публичная страница бота: https://t.me/fmusbot — публичный API для внешнего каталога на странице не указан.
