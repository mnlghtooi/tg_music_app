## Варианты без личной MTProto-сессии
### 1. Прямой личный диалог ботов
Telegram Bot API позволяет sendMessage с @username другого бота, если Bot-to-Bot Communication Mode включён у обоих.
У @fmusbot режим не подтверждён. Нельзя обещать работу, пока нет фактического ответа.
Источник: https://core.telegram.org/bots/features#bot-to-bot-communication

### 2. Общая тестовая группа
Для адресованной команды или ответа между ботами Telegram требует режим хотя бы у одного бота. Включённый режим у нашего бота плюс права администратора/отключённая privacy позволяют получать обычные сообщения других ботов в группе.
Не установлено: можно ли добавить @fmusbot в нужную группу, какие команды он принимает и отдаёт ли аудио без ручного выбора.
Даже получение меню не означает полной интеграции: Bot API не предоставляет универсальное нажатие чужой callback-кнопки; answerCallbackQuery отвечает на собственный входящий callback, а не нажимает кнопку.
Эксперимент: приватная группа → оба бота → включить режим у нашего → одна адресованная команда, подтверждённая справкой @fmusbot → получить и классифицировать ответ. Не угадывать множество команд. Не добавлять циклические автоответы.
Источник: https://core.telegram.org/api/bots/bot-to-bot

### 3. Выбор пользователем через inline или пересылку
Официальный inline-механизм: пользователь вводит @username запрос, выбирает результат, Telegram отправляет выбранное содержимое получателю.
Источник: https://core.telegram.org/bots/inline
Вариант для проверки: в чате нашего бота пользователь вводит @fmusbot запрос и выбирает трек. Если наш бот получает message.audio или документ с audio MIME, backend регистрирует файл для библиотеки.
Именно текущая поддержка @fmusbot и получение сообщения нашим ботом требуют живого теста; каталоги ботов не считаются надёжным подтверждением.
Резерв: пользователь вручную пересылает полученное аудио нашему боту.
Это импорт выбранного трека, а не встроенная выдача поиска в Mini App.
switch_inline_query нашей кнопки и Telegram.WebApp.switchInlineQuery относятся к нашему боту; их нельзя объявлять способом произвольно вызвать inline другого бота.
Bot API Message содержит via_bot и audio; сам выбор результата пользователем отличается от автоматического диалога двух ботов.
Источник: https://core.telegram.org/bots/api

### 5. Telegram Business
Документирован Chat Access Mode: подключённый к бизнес-аккаунту бот может отправлять сообщения другим ботам в доступных чатах; режим нужен отправителю.
Это отдельная архитектура с доступом к чатам, не публичный API @fmusbot; не выбрана как простой вариант.
Источник: https://core.telegram.org/api/bots/bot-to-bot

## Найденный сторонний код
Проверены README и исходники:
- https://github.com/serdeltomas/telegram-bot-bridge
- https://github.com/serdeltomas/telegram-bot-bridge/blob/main/telethon_client/client.py
- https://github.com/serdeltomas/telegram-bot-bridge/blob/main/telethon_client/parser.py
Он использует TelegramClient с API_ID/API_HASH и user_session; отправляет текст, ожидает кнопку callback с префиксом dl:, нажимает её и скачивает документ.
Это подтверждает существование реализации моста, а не его текущую работоспособность. Он не устраняет необходимость my.telegram.org. Формат callback может измениться; копировать его без живой проверки нельзя.
Не запускали и не копировали этот код в приложение.

## Backend остаётся необходимым
Импорт или прямой поиск требуют серверного процесса на Windows/VPS, токена нашего бота и HTTPS для Mini App на iPhone.
Нельзя выдавать в браузер прямой URL Telegram file API: он содержит bot token.
Стандартный getFile ограничивает скачивание 20 MB и выдаёт временную ссылку. Для больших файлов отдельное решение, например локальный Bot API server, требует оценки сложности.
Нужны хранение библиотеки по пользователям, авторизация Telegram initData и HTTP Range для перемотки.
Источник: https://core.telegram.org/bots/api#getfile

3. Если нужна полностью встроенная выдача и первые варианты не работают — частный API владельца или существующий Telethon probe после снятия ограничения my.telegram.org.
4. После получения одного разрешённого аудио — backend и сквозной тест на iPhone.
Не считать поиск, скачивание и разрешение на распространение одной и той же проверкой.
