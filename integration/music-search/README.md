## Запуск
1. Распаковать архив.
2. Дважды нажать START.cmd. Python уже установлен на тестовом Windows-ПК пользователя.
3. Откроется браузер с приложением. Кнопка поиска справа сверху → ввести название или исполнителя → нажать на результат.
Первый запуск устанавливает yt-dlp и httpx с HTTP/2 в локальную .venv. В архиве есть hls.js; при запуске исходников он загружается с проверкой SHA256.
Логины, пароли, Telegram API ID и платные ключи не требуются.
Окно запуска держать открытым; Ctrl+C останавливает сервер.

## Телефон
Запуск также пытается поднять временный HTTPS-туннель Cloudflare и печатает PHONE_URL. Эту личную ссылку можно открыть на iPhone. При отсутствии cloudflared Windows x64 он загружается с официального GitHub Cloudflare в .tools.
Туннель требует сети и может быть заблокирован сетью/средой. Его URL не является постоянным хостингом. При каждом запуске личный ключ меняется; URL туннеля также может измениться.
Если туннель не работает, поиск в локальном браузере продолжает работать. В среде разработки внешний HTTPS-туннель не прошёл проверку (502), работоспособность на Windows пользователя ещё не подтверждена.
Текущий Mini App на GitHub Pages не переключён автоматически. Это отдельно запускаемая версия того же интерфейса. Python не запускается на GitHub Pages.

## Реализовано
- По 10 записей на странице, назад/вперёд, загрузка нужной страницы по offset; кеш поиска 5 минут.
- Выбор SoundCloud/Audius в окне поиска.
- Поиск не изменяет текущую очередь до явного выбора трека.
- Выбранный трек запускается в существующем плеере с мини-плашкой, полным экраном, лайком, дизлайком, плейлистами и подсветкой.
- Публичный поток HLS проксируется нашим backend. На iPhone используется native HLS, в Chrome — hls.js.
- MP3/FFmpeg-конвертация не нужна; поток не сохраняется целиком.
- Записи длительностью до 30 секунд отмечаются как превью/короткие записи. Некоторые другие результаты могут быть недоступны или ограничены источником; полная дискография не гарантируется.
- Сессия доступа к личному серверу через случайную ссылку и HttpOnly cookie; API без этой сессии возвращает 403.
- Произвольные URL браузер не передаёт: разрешены только идентификаторы и выданные сервером токены. Media proxy ограничен доменами SoundCloud.
- DRM/платные/приватные ограничения не обходятся, cookies аккаунта не используются.
- Библиотека остаётся в localStorage. У другой ссылки/домена отдельное хранилище: библиотека старого GitHub Pages автоматически сюда не переносится.

## Обновление 0.6.2 — рефакторинг поиска
Поиск вынесен в search_service.py. Раньше запрос к api-v2.soundcloud.com/search/tracks проходил через транспорт yt-dlp под общей блокировкой. Теперь используется постоянный httpx.Client с пулом соединений и поддержкой HTTP/2; yt-dlp остаётся для начального получения публичного client_id и извлечения потока при воспроизведении. Данные треков преобразуются напрямую из JSON, без поискового экстрактора.
- Блокировка только на инициализации/обновлении client_id; сетевые запросы поиска не сериализуются.
- До четырёх независимых поисков одновременно; одинаковые одновременные запросы ждут один общий результат.
- Кеш: 5 минут, максимум 100 страниц. Страница по-прежнему 10 треков, запрос 11 для определения следующей.
- Устаревший client_id обновляется один раз после 401/403. На 429 повторных запросов нет.
- START.cmd проверяет новые зависимости и устанавливает их в существующую .venv автоматически.

Сравнение до/после в одной среде 18.10.2026, после прогрева credentials, пустой кеш страниц, по одному запросу каждой версии. Порядок: сначала старая, затем новая версия; это небольшая выборка, не нагрузочный тест и не гарантия скорости в другой сети.

## 0.7.1 — быстрый старт аудио и лоадер
Поток уже передавался через HLS, без ожидания всего трека. Устранена лишняя подготовка перед стартом и расходы передачи сегментов:
- stream_service.py выбирает один публичный доступный формат вместо полного извлечения всех форматов yt-dlp. Предпочтение: полная запись, HLS, AAC 160 kbps; качество специально не понижается. При отсутствии формата (404) допускается одна альтернатива, ограничения 429/DRM/BLOCK не обходятся.
- Метаданные и track_authorization из поиска/плейлиста остаются на сервере до 5 минут, до 1000 записей. При выборе песни из сохранённой библиотеки без метаданных выполняется один дополнительный запрос tracks/id.
- Кеш адреса потока — 5 минут, максимум 200 записей. Одновременные запросы одного трека объединяются; максимум 4 независимых подготовки аудио.
- Media proxy использует постоянный httpx.Client с HTTP/2 и пулом соединений. Бинарные данные передаются по 16 KiB по мере прихода, без чтения сегмента целиком. Range и Content-Range сохраняются. Манифесты переписываются в токены как раньше.
- На компьютере HLS обрабатывается hls.js: целевой запас 20 с, верхняя настройка 30 с (границы сегментов могут дать превышение), буфер позади 30 с. На iPhone/iPad сохранён native HLS для системного плеера; запасом управляет Safari/iOS, эти настройки на него не распространяются.
- Исправлен выбор desktop HLS-плеера: native HLS Chrome может не воспроизводить некоторые MP3-превью; desktop использует hls.js при наличии MSE. Реальный MP3-превью тест прошёл.
- Записи с policy=BLOCK отмечены «недоступен у источника», не ставятся в очередь по странице, нажатие не начинает длительный сетевой запуск. Это ограничение источника, не ошибка поиска.
- На месте Play в мини-плеере и полном плеере появляется вращающийся лоадер сразу после выбора трека/возобновления. Он также показывается при ожидании данных/перемотке. Playing убирает лоадер и показывает Pause; ошибка или пауза возвращает Play. Нажатие на лоадер отменяет намерение начать воспроизведение.
- Есть aria-busy и доступная подпись кнопки; prefers-reduced-motion отключает вращение. Устаревшая ошибка предыдущего трека не меняет состояние нового.
- Версия увеличена только до 0.7.1, вторая цифра не менялась. Изменения запуска из откаченной 0.6.3 не включены.

### Карточки исполнителей и релизов (0.7.5)

В поиске нажмите на исполнителя, альбом или плейлист. Карточка показывает обложку, описание (если источник его опубликовал) и доступные записи. У исполнителей SoundCloud и Audius есть разделы «Дискография», «Треки» и «Плейлисты»; Bandcamp показывает публичные релизы. Это каталог конкретного сервиса, а не обещание полной мировой дискографии.

Имя исполнителя рядом с треком открывает профиль. «К альбому» и меню «⋯» открывают релиз по связи, которую передал источник. SoundCloud использует список альбомов трека, Bandcamp — родительский альбом в метаданных; треки, открытые из альбома, сохраняют эту связь в библиотеке и JSON-копии. Для треков Audius, найденных отдельно, связь с альбомом сейчас не определяется; переход к альбому доступен для треков, открытых из его карточки. Название трека запускает воспроизведение. Отсутствующая связь не заменяется поиском по похожему названию.

Плейлисты SoundCloud и Audius используют такую же карточку со списком треков. В Bandcamp отдельные публичные плейлисты этим способом не поддерживаются. Старые сохранённые треки получают сведения при первом переходе. Карточки не меняют статус незавершённого прототипа переноса музыки.
