# Music Lab 0.6.0 — поиск SoundCloud и единый плеер
## Запуск
1. Распаковать архив.
2. Дважды нажать START.cmd. Python уже установлен на тестовом Windows-ПК пользователя.
3. Откроется браузер с приложением. Кнопка поиска справа сверху → ввести название или исполнителя → нажать на результат.
Первый запуск устанавливает yt-dlp в локальную .venv. В архиве есть hls.js; при запуске исходников он загружается с проверкой SHA256.
Логины, пароли, Telegram API ID и платные ключи не требуются.
Окно запуска держать открытым; Ctrl+C останавливает сервер.

## Телефон
Запуск также пытается поднять временный HTTPS-туннель Cloudflare и печатает PHONE_URL. Эту личную ссылку можно открыть на iPhone. При отсутствии cloudflared Windows x64 он загружается с официального GitHub Cloudflare в .tools.
Туннель требует сети и может быть заблокирован сетью/средой. Его URL не является постоянным хостингом. При каждом запуске личный ключ меняется; URL туннеля также может измениться.
Если туннель не работает, поиск в локальном браузере продолжает работать. В среде разработки внешний HTTPS-туннель не прошёл проверку (502), работоспособность на Windows пользователя ещё не подтверждена.
Текущий Mini App на GitHub Pages не переключён автоматически. Это отдельно запускаемая версия того же интерфейса. Python не запускается на GitHub Pages.

## Реализовано
- До 30 найденных записей по названию/исполнителю через SoundCloud; кеш поиска 5 минут.
- Выбор SoundCloud/Audius в окне поиска.
- Поиск не изменяет текущую очередь до явного выбора трека.
- Выбранный трек запускается в существующем плеере с мини-плашкой, полным экраном, лайком, дизлайком, плейлистами и подсветкой.
- Публичный поток HLS проксируется нашим backend. На iPhone используется native HLS, в Chrome — hls.js.
- MP3/FFmpeg-конвертация не нужна; поток не сохраняется целиком.
- Записи длительностью до 30 секунд отмечаются как превью/короткие записи. Некоторые другие результаты могут быть недоступны или ограничены источником; полная дискография не гарантируется.
- Сессия доступа к личному серверу через случайную ссылку и HttpOnly cookie; API без этой сессии возвращает 403.
- Произвольные URL браузер не передаёт: разрешены только идентификаторы и выданные сервером токены. Media proxy ограничен доменами SoundCloud.
- DRM/платные/приватные ограничения не обходятся, cookies аккаунта не используются.
- Библиотека остаётся в localStorage. У другой ссылки/домена отдельное хранилище: библиотека старого GitHub Pages автоматически сюда не переносится.

- Backend-поиск «Scott Buckley»: 30 результатов.
- HTTP-авторизация, реальная HLS playlist, получение 2048 байт аудиосегмента через media proxy.
- Сквозной тест Chrome 390×844: живой поиск 30 результатов, реальное проигрывание >1 секунды записи длительностью 247.274705 секунды, лайк, избранное/подсветка, пауза, отсутствие ошибок JS.
- Это не проверка полного прослушивания, качества совпадения или фонового поведения на iPhone.

## Ручные проверки
- [ ] START.cmd на обычном Windows пользователя; первый и повторный запуск.
- [ ] Несколько русских и зарубежных исполнителей; выбор точной записи вместо кавера/ремикса.
- [ ] Пустой запрос, отсутствие результатов, сеть/недоступный трек.
- [ ] Поиск во время воспроизведения не прерывает музыку.
- [ ] Полный трек, 30-секундная запись, следующая/предыдущая, автоокончание.
- [ ] Перемотка, пауза, сворачивание плеера, лайки и плейлисты.
- [ ] iPhone: HTTPS, запуск звука по нажатию, блокировка, Media Session, Bluetooth.
- [ ] Временный туннель работает в сети пользователя; остановка сервера прекращает доступ.
- [ ] Старые плейлисты в GitHub Pages не потеряны; миграция между доменами пока не реализована.
